# Threat Model (v0.3 — Desktop & Track L Sync, updated 2026-11-25)

PAI ingests untrusted internet data, may eventually rewrite its own code and drives desktop workflows via Tauri/bridge APIs, local Ollama, cloud AI pools, MCP servers, and OS automation. This document lists what we defend, from whom, and what is still open. It is a living document: **every phase and every new feature must update it alongside [TRUST_BOUNDARY_DIAGRAM.md](TRUST_BOUNDARY_DIAGRAM.md) and [STRIDE_THREAT_MODEL.md](STRIDE_THREAT_MODEL.md) before completion (per [AGENTS.md](../AGENTS.md)).**

See also:
- [Trust Boundary Diagram & Inventory](TRUST_BOUNDARY_DIAGRAM.md) — End-to-end Mermaid trust boundary diagrams (`B1`–`B8`) and enforcement table.
- [STRIDE Threat Model](STRIDE_THREAT_MODEL.md) — Full Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, and Elevation of Privilege analysis plus prioritized P0–P2 remediation backlog.

## 1. Assets
* The user's files, credentials (incl. `~/.pai/cloud_ai.json` API keys), memories (`~/.pai/memory/`), and identity on the host.
* The user's queries, session transcripts, and working data (privacy).
* The integrity of the engine (`pai-core.exe`, `pai-desktop.exe`, `research/`) and of its Safety Constitution (`docs/CONSTITUTION.md` pinned in `research/trust.json`).
* Host availability (RAM/CPU/disk/VRAM) and cloud API spend/quotas.

## 2. Trust Boundaries
Summary view (see full multi-subsystem Mermaid diagrams and `B1`–`B8` inventory in [TRUST_BOUNDARY_DIAGRAM.md](TRUST_BOUNDARY_DIAGRAM.md)):
```text
 Internet / Cloud AI / MCP (UNTRUSTED) ──► net_guard / url_policy ──► DataVerifier / ingest ──► SecureBuffer ──► Reasoner
                                                                                                      │
 AI-generated code (UNTRUSTED) ──► Tier 1 AST ──► Tier 2 OS Sandbox (AppContainer/bwrap/WSB) ──► HMAC Verdict ──► Workspace
                                                                                                      │
 Desktop WebView / Loopback Caller ──► Tauri Shell (pai-desktop) ──► bridge_server (127.0.0.1:8765) ──► Local Store / Tools
```
Everything left of the Reasoner, Sandbox Gate, or Bridge Boundary is untrusted until verified. Generated code is untrusted *even though PAI wrote it*.

## 3. Threat Register

| ID | Threat | Phase 1 status | Mitigation / next step |
|----|--------|----------------|------------------------|
| T1 | **Local file read / SSRF** — a URL such as `file:///…`, `http://127.0.0.1`, or `169.254.169.254` makes the engine read local files or hit internal services | **Fixed** (found in review: `file://` was accepted) | `net_guard` (Python) and `url_policy.rs` (Rust) enforce one documented table (`NET_POLICY.md`): scheme allow-list, canonical IP literals only, blocked CIDRs including IPv6 transition/embedded-IPv4 prefixes (NAT64, 6to4, Teredo, SIIT, IPv4-compatible), ports 80/443 in canonical form, no credentials; re-validated on each redirect. Found in the 2026-10-07 review: the first explicit table missed the transition prefixes (fixed in `70fd7f6`, 87 golden vectors). Residual: any table can be incomplete; adversarial vectors from an independent source are part of review |
| T2 | **DNS rebinding** — name resolves to a public IP at check time, a private one at connect time | Partial | `raw` transport connects to the validated IP; `urllib` still re-resolves. Rust provides a pure post-resolution check (`validate_resolved_ips`); the native client that pins the connection to the validated IP is VS3 work |
| T3 | **Prompt injection via web content** — "ignore previous instructions…" inside a page steers the reasoner | Mitigated (heuristic) + **blast radius limited** (ADR-006) | Screening (default reject) and untrusted-data fencing reduce the odds; the **capability broker** limits the damage if screening fails: deny-by-default grants, path scoping, taint tracking (untrusted context ⇒ every non-read tool needs a human; no confirmation channel ⇒ denied), hash-chained audit. Residual: confirmation UI is Phase 5; taint is per task |
| T4 | **Resource exhaustion** — giant bodies, slow-loris, decompression bombs | Mitigated | Byte caps on every read, total deadline (raw), 6 s socket timeout, `Accept-Encoding: identity`, content-type filter |
| T5 | **Residual data in RAM** after a task | Partial | `SecureBuffer` zeroes + verifies. Open: `str` copies, pagefile/swap, crash dumps. Phase 3: Rust `zeroize`, `VirtualLock`, disable WER dumps for the process |
| T6 | **Query privacy leak** — topics are sent to Wikipedia/DuckDuckGo | **Mitigated by user controls** (ADR-002) | Domain allow-list, visible outbound log (exact URLs), `--offline`, local-first `--knowledge-dir`. Residual: allowed domains still see queries and the IP address; the user chooses offline/local for sensitive topics |
| T7 | **Malicious / drifting self-modification** | Designed; Tier 0/1 + updater + sandbox policy prototyped | `RSI_SAFETY_SPEC.md`; externally signed releases and a separate updater that owns the Constitution hash (ADR-005); Windows Sandbox isolation checklist as code (ADR-003) |
| T8 | **TLS interception / bad certificates** | Mitigated | Default certificate and hostname verification; never disabled |
| T9 | **Telemetry spoofing / IPC abuse** (Phase 2) | Open | Named-pipe ACL restricted to the current user, message schema validation, versioned schema |
| T10 | **Supply chain** | Low | Prototype is stdlib-only; before adding dependencies: pin versions + hashes, review licences |
| T11 | **Hostile sandbox output** — the one writable folder is attacker-controlled | Mitigated (policy as code) | `read_sandbox_results`: exactly one `results.json`, ≤ 256 KB, strict schema, no links/extra files (ADR-003) |
| T12 | **Malicious, tampered or rolled-back update** | Mitigated (prototype) | Ed25519 signature over manifest, per-file SHA-256, anti-rollback counter, pinned Constitution hash, TOCTOU re-verification, atomic install (ADR-005). Residual: OS-level privilege separation is installer work; key custody procedure TBD |
| T13 | **External inference process memory retention** — local model runner (Ollama / llama-server) keeps prompt and generated tokens resident in external process memory and VRAM across tasks | Partial / Residual risk | Python internal buffers zeroized post-task (T5); external model server memory retention bounded by server idle timeout (e.g. keep_alive). Residual: external process memory zeroization is outside the Python agent boundary. ADR-008/M1: request `keep_alive: 0` for sensitive runs and verify with `ollama ps`; in-process Rust inference with `zeroize` is the long-term answer |
| T14 | **Trust-label injection** — context text claiming a higher-trust source (e.g. `[Source: local_knowledge]`) to influence conflict resolution | **Fixed** | Cryptographic per-task nonce (`secrets.token_hex(8)`); parser accepts `[[SRC:<nonce>:<source>]]` only; in-band text headers ignored; incoming `[[SRC:` tokens neutralized |
| T15 | **Untrusted local files and documents** — a file under analysis contains instructions aimed at the model, symlinks or `..` paths that escape the chosen folder, or secrets that would be sent to the model | Planned (M3/M4) | Allow-listed roots, real-path containment, extension allow-list, size caps, binary and secret-file skipping, fenced untrusted text, no tools exposed during analysis; adversarial tests required before merge (`LOCAL_ASSISTANT_SPEC.md`) |
| T16 | **Execution of model-generated code** in the verify loop | **Designed (ADR-011 v2 & M2 Spec v2)**; M1.1 runner prototype | Multi-tier defense-in-depth: Tier-1 AST guard (36 forbidden modules, dangerous builtins, nuanced path/attribute rules), Tier-2 OS-level sandbox (Windows AppContainer with zero capabilities + Job Objects; Linux bubblewrap/Landlock + unshare-net + rlimits) with startup capability probe & fail-closed refusal (Exit 5), bounded repair loop ($N \le 3$) with frozen tests and vacuous pass check, zero test-set leakage, race-free exclusive staging (`O_CREAT \| O_EXCL`). Validated against 11-attack adversarial matrix (`docs/M2_VERIFY_LOOP_SPEC.md`). Residual: weaker than a full hardware-virtualized hypervisor VM (ADR-003 fallback). |
| T17 | **Local web interface abuse** — another web page calls `localhost`, DNS rebinding, token theft | Planned (M6) | Bind `127.0.0.1` only, random port, per-session token, `Host`/`Origin` checks, no CORS, no server-side history, picker limited to allow-listed roots |
| T18 | **Self-training poisoning and memorization** — web-tainted trajectories or private data enter training; a regressed model is promoted | Designed (ADR-008) | Self-play problems with unit tests, tainted trajectories excluded, private data opt-in only, hardware-aware scheduling, frozen evaluation sets, promotion gate with signed release and rollback. Residual: unknown unknowns in model behaviour |
| T19 | **Misleading numeric output** — forecasts or analyses read as certainties or contain invented figures | Planned (M5) | Numbers computed by tested code, backtest error and prediction interval always shown, refusal on insufficient data, language model may only narrate computed values; claims policy applies |
| T20 | **Model supply chain and licensing** — a downloaded model is tampered with or its licence forbids the intended use (including training on its outputs) | Planned (M1) | Named allow-list of models, model card (source, licence, SHA-256, measured RAM), hash re-checked after download, licence reviewed before use. Residual: weights are opaque; behaviour is checked only through evaluations. Thinking-mode and truncation behaviour is part of the bake-off |
| T21 | **Model-selection manipulation** — content (files, web pages, model output) names or steers a model/endpoint choice, or forces a fallback to a weaker or unvetted model | **Mitigated (M1b/M1c)** | Router accepts model names only from allow-list; task class resolved exclusively from command arguments; endpoint verified local loopback; hostile context tests pass in `test_router.py`. User allow-lists strictly filter candidates. |
| T22 | **API key leak or theft** — key committed to the repository, written to logs/config/crash output/process arguments, read from the environment by a hostile process, or extracted by content that asks the model to reveal it | **Mitigated (at rest)** | Config scanner in `config.py` rejects secrets in user config; `credential_store.py` encrypts cloud API keys at rest using Windows DPAPI (`CryptProtectData`) with atomic 0o600 fallback on POSIX; `bridge_server.py` masks keys in `/api/cloud/config`; `mcp_client.py` scrubs child env vars; tested in `test_credential_store_and_memory.py`, `tools/check_secrets.py`. |
| T23 | **Data egress to cloud providers** — prompts, file contents or secrets leave the machine; the provider retains them beyond our purge; hostile content tries to trigger a cloud call | Planned (M1d) | Local-only default; cloud needs provider enabled **and** per-run consent listing what is sent; secret-skipped files never sent; content cannot enable cloud or pick a provider (T21); visible outbound log with byte counts; "sent to provider" notice; `--offline`. Residual: the provider's retention is outside our control |
| T24 | **Runaway cost** — loops, retries or injected instructions cause large paid calls | Planned (M1d) | Per-run and per-day spend caps from the provider card, counted locally; bounded retries; no model-initiated calls; hard stop with a clear message |
| T25 | **Provider endpoint spoofing or redirection** — custom base URL, DNS/redirect trick or edited configuration sends the key to an attacker host | **Mitigated (Custom Endpoints)** | Standard provider hosts hardcoded in `CLOUD_PROVIDERS`; custom endpoints require HTTPS for remote targets and are screened with `net_guard` SSRF checks; Gemini uses `X-Goog-Api-Key` headers rather than query parameters; tested in `test_ssrf_and_grounding.py`. |
| T26 | **Machine-profile, configuration or catalog tampering** — edited calibration claims more free RAM than exists (out-of-memory), config enables an unvetted model or provider, a model is downloaded from an unvetted source | **Mitigated (M1c)** | Machine profile schema-validated and cross-checked against live hardware (divergence > 35% rejected); unknown keys rejected fail-closed; uncalibrated models apply 1.5x conservative multiplier; tested in `test_config.py`. |
| T27 | **Check-then-launch (TOCTOU) gap on per-user binary execution** — a hostile process running under the user's account replaces `ollama.exe` between `WinVerifyTrust` verification and `subprocess.Popen` execution | **Residual risk (Accepted)** | Target binary `%LOCALAPPDATA%\Programs\Ollama\ollama.exe` is verified before execution via Authenticode (WinVerifyTrust); PATH lookup is prohibited (T21/ADR-014); `bridge_server.py` `_spawn_ollama_daemon` delegates to `OllamaServiceManager`; tested in `test_service_manager.py` and `test_desktop_security.py`. Residual: in a standard per-user install without administrator privileges, another process running with identical user permissions has write access to `%LOCALAPPDATA%`, creating an unavoidable time-of-check to time-of-use gap. Defense in depth: single-user threat boundary. |
| T28 | **Desktop auto-updater signature & integrity bypass** — `PAIUpdateManager` (`desktop/bridge_server.py`) and `desktop/apply_pending_update.py` stage and extract `.zip` releases without verification, or silently reject valid CI release zips missing offline `manifest.sig` | **Mitigated (Desktop / Honest Scope)** | `bridge_server.py` validates update URLs via `net_guard` and checks downloaded zip SHA-256 and size against `manifest.json`; `apply_pending_update.py` enforces full `research.updater.Updater` Ed25519 + Constitution SHA-256 verification whenever `manifest.sig` or `PAI_REQUIRE_SIGNED_UPDATE=1` is present, and for CI-built GitHub releases without `manifest.sig` enforces SHA-256 digest match, SemVer non-downgrade, and traversal/symlink/250 MiB zip-bomb rejection; fails closed on mismatches or network errors; tested in `test_updater.py` and `test_desktop_security.py`. Residual: CI-built GitHub pre-releases rely on TLS + SHA-256 manifest verification unless `PAI_REQUIRE_SIGNED_UPDATE=1` and offline-signed manifests are used. |
| T29 | **Cross-origin / unauthenticated local bridge abuse** — `desktop/bridge_server.py` binds `127.0.0.1:8765` with `Access-Control-Allow-Origin: *` and no session token or `Origin`/`Host` validation | **Mitigated (Desktop)** | Replaced wildcard CORS with strict `Origin` echo (`tauri.localhost` / loopback port) with `Vary: Origin`; validated `Host` header against loopback port (403 on mismatch); required per-launch `X-PAI-Token` on all `/api/*` and `/generated_images/*` endpoints via constant-time `hmac.compare_digest`; ephemeral `--port 0` dynamic binding; tested in `test_desktop_security.py`. |
| T30 | **Secret leakage via Desktop workspace/context readers** — `bridge_server.py` (`get_project_codebase_context`, `_handle_project_file_content`, `_handle_project_file_save`) lacks `ingest.is_secret_file` and `ingest.scan_secret_content` checks | **Mitigated (Desktop)** | Desktop codebase context and file endpoints enforce `is_secret_file` and `scan_secret_content`, reject symlinks/reparse points, and run `ast_guard` on `.py` saves; tested in `test_desktop_security.py` and `test_credential_store_and_memory.py`. |
| T31 | **Unbounded Desktop background thread / job spawning** — `/api/antigravity/run` and `/api/cowork/tasks/run_auto` spawn raw daemon threads without concurrency caps | **Mitigated (Desktop)** | Bound background agent executions using `_agent_executor = ThreadPoolExecutor(max_workers=4)`; 16 MiB request body limit; 10 MiB archive decompression limit; tested in `test_desktop_security.py`. |
| T32 | **Unbrokered MCP server command registration & env leakage** — `/api/mcp/save` accepts arbitrary commands and `StdioMCPTransport` inherits `os.environ.copy()` | **Mitigated (Desktop/MCP)** | `mcp_client.py` scrubs child env vars to strict allowlist (stripping API keys), blocks unpinned `npx -y` and shell interpreters, and enforces `ToolBroker` confirmation gating (`confirm: true` on `/api/mcp/save`, `/api/mcp/toggle`); tested in `test_agentic_containment.py`. |
| T33 | **Unconfirmed OS automation & Antigravity steering** — `/api/antigravity/run` runs `agy --dangerously-skip-permissions` and `automation.py` launches apps/URLs without strict allowlists or human confirmation | **Mitigated (Desktop/Auto)** | Removed `--dangerously-skip-permissions` from unattended runs in `antigravity_driver.py`, enforced `ToolBroker` confirmation on `/api/antigravity/run`, and bounded continuous agent tasks; restricted desktop apps strictly to `_APP_ALLOWLIST` with `shell=False` and path resolution, blocked dangerous commands via `_DANGEROUS_CMD_GUARD`, and enforced human-in-the-loop pre-fill with clipboard backup for WhatsApp and Email compose; safely intercepted automation chat tasks in `bridge_server.py`; tested in `test_agentic_containment.py` and `test_pc_automation.py`. |
| T34 | **Tauri WebView CSP disabled (`"csp": null`)** — XSS in `desktop/ui/` could access `window.__TAURI__` (`withGlobalTauri: true`) or bridge endpoints | **Mitigated (Desktop)** | Configured strict Content Security Policy in `desktop/src-tauri/tauri.conf.json` restricting network origins to loopback and self; added `sanitizeUrl` in `desktop/ui/app.js` blocking `javascript:`, `data:`, `vbscript:`; added delegated event listeners for copy controls; tested in `test_desktop_security.py`. |
| T35 | **Python import / DLL search-order hijack on direct script execution** — invoking Python scripts directly skips `packaging/launcher/launcher.c` sanitization | **Mitigated (via `pai.exe`)** | `launcher.c` verifies `pai-core.exe` SHA-256 via BCrypt, strips `PYTHONPATH`/`PYTHONHOME`/`PYTHONSTARTUP`, and sets safe DLL search order. Residual: direct `python` invocations rely on caller environment hygiene. |
| T36 | **Incomplete Air-Gap & Silent Cloud Egress** — turning off internet left cloud LLM APIs, image generation, fact-checking, update checking, or web search active or attempting outbound sockets without prompt-level confirmation or local model fallback | **Mitigated (Desktop & Research)** | Fail-closed offline enforcement across `cloud_ai.py` (`query_cloud_ai`, `generate_image_cloud`, `run_model_fusion`, `test_provider_connection`), `internet_service.py` (`search_web`, `fetch_live_weather`, `geocode_location`, `get_live_grounding_context`, `fetch_url_text`), and `desktop/bridge_server.py` (`/api/settings/toggle`, `/api/factcheck`, `/api/image/generate`, `/api/update/*`, `/api/chat`); interactive confirmation modal in `desktop/ui/index.html` detailing affected services before disconnect; automatic fallback to local Ollama models; tested in `test_offline_airgap.py`. |
| T37 | **UIA Screen Prompt Injection, Runaway Mouse/Keyboard Steering & Screenshot Egress** — malicious window titles/UIA labels steer desktop actions, runaway cursor clicks PAI Desktop or triggers destructive shortcuts, or screenshots leak to Cloud Vision | **Mitigated (Desktop Control / MCP)** | `desktop_control.py`, `windows_mcp_server.py`, and `desktop_orchestrator.py` gate all Win32/UIA actions via `ToolBroker`, defang UIA text (`tainted=True`), enforce `(0,0)` corner failsafe + `/api/desktop/abort` + self-window click guard + blocked hotkeys + `MAX_STEPS=10` cap, require `/api/desktop/control_toggle` `confirm: true` and HITL `Approve & Send` via `/api/desktop/confirm_action`, and respect active model & offline air-gap checks for Vision fallback; tested in `test_desktop_control.py` and `test_windows_mcp_server.py`. |
| T38 | **Runaway Reasoning Loops, Premature Incomplete Answers & Context OOM** — multi-step Cowork/Swarm runs repeat stalled actions indefinitely, expand local `num_ctx` beyond RAM headroom, complete with unresolved `PENDING` reasoning leaves or broken syntax, or leak secrets/markers into `ThoughtGraph` persistence | **Mitigated (Reasoning / Cowork v2)** | `thought_graph.py` & `crash_reasoning_mcp.py` scrub secrets via `scan_secret_content` and defang envelope markers before atomic JSON writes; `thinking_engine.compute_adaptive_context_budget` clamps `COMPRESSED` `num_ctx <= 4096`; `reasoning_engine.RadialExplorer.verify_zero_incomplete_leaves` and `cowork.verify_task_quality` reject incomplete leaves or Python syntax errors; `StuckDetectorWatchdog` halts repetition loops, heartbeat timeouts, and confidence collapses cleanly onto checkpointed recovery branches (`max_recoveries=3`); tested in `test_deep_reasoning.py` and `test_swarm_and_cowork_v2.py`. |
| T39 | **Malicious Plugins/SKILL.md, HTTP/SSE MCP SSRF, Elicitation Credential Harvesting & Context Bloat** — imported plugin or `SKILL.md` injects override prompts/secrets; Streamable HTTP MCP targets cloud metadata or runs while offline; external MCP emits leaked tokens or harvests passwords via `elicitation`; large tool catalogs overflow model context or escalate privileges across Cowork roles | **Mitigated (MCP Hub / Plugins)** | `plugin_manager.PluginScanner` grades plugins (`0-100`) and blocks secret leaks, instruction-override markers, unpinned `npx -y`, and SSRF URLs; `StreamableHttpMCPTransport` validates targets through `net_guard` and checks offline air-gap status before requests; `MCPVaultManager` encrypts tokens via DPAPI (`credential_store.py`) without storing plaintext in `mcp_servers.json`; `MCPServerPolicy` (`read_only`, `lockdown_mode`, `toolsets`), `is_secret_elicitation_schema`, and `redact_and_sanitize_mcp_text` harden tool/resource/elicitation channels; `ContextWindowAssembler` (`context_engine.py`) applies token budgeting + observation masking; `StuckDetectorWatchdog.record_tool_failure` and `multi_agent.get_role_agent_card` isolate agent roles; tested in `test_mcp_and_plugin_ecosystem.py`. |
| T40 | **Local C++ Sidecar Hijack, RAM/VRAM Exhaustion, Installer Archive Traversal & Free Cloud Image Payload Spoofing** — rogue `llama-server` / `sd-cli` picked from `PATH` or symlinked binary; oversized 27B/FLUX weights cause silent OOM; automated GitHub/HF runtime downloads suffer zip-slip, spoofed ZIP `file_size`, HTML payloads, UNC paths, or SSRF redirects; free image endpoints bypass offline air-gap or return HTML/script payloads masquerading as images | **Mitigated (Sidecars / Image Gen / Provisioner; Residual on floating release assets)** | `local_sidecars.py` rejects `PATH` lookup and symlink/reparse binaries (pinning `~/.pai/bin/` and `%LOCALAPPDATA%\Programs\{PAI,llama.cpp,stable-diffusion.cpp}\`), restricts sidecar HTTP strictly to loopback `127.0.0.1:11435` with `shell=False`, enforces Gate 1 disk/hardware checks (`assess_install_and_run_readiness`) and Gate 3 pre-load RAM/VRAM admission (`check_runtime_admission`, 64-layer offload calc, SSE streaming, FLUX `--offload-to-cpu`/`--clip-on-cpu`, idle 300s reaper), syncs custom `models_path` storage directories, verifies FLUX multi-file companions, redacts local paths in `_format_sdcpp_friendly_error`, and validates PNG/JPEG magic bytes before saving; `memory_optimizer.py` performs mutual exclusion between Ollama, `llama.cpp`, and `sd.cpp`, trims only own/sidecar Win32 working sets (read-only external advisory, never kills user processes), and exposes `/api/system/memory_status` & `/api/system/optimize_memory`; `cloud_ai.py` validates keyless Pollinations + AI Horde (`stablehorde.net`) endpoints via `net_guard` and `is_internet_enabled()` polling checks; `bridge_server.py` supports keyless FLUX fallback on `cloudflare-flux-schnell`/`hf-flux-schnell` when online (failing closed when offline), validates `POST /api/image/save_as` (magic bytes, basename sanitization, symlink check, HITL native folder picker), and guards Q&A prompts on image models via `_looks_like_image_generation_request`; `sidecar_installer.py` enforces strict GitHub/HuggingFace host allowlisting + `net_guard` SSRF redirect checks, offline air-gap fail-closed checks, and zip-slip/symlink/512 MiB extraction caps; tested in `test_sidecars_and_image.py` and `test_offline_airgap.py`. |

## 4. Out of Scope (for now)
Physical access, a compromised OS or kernel, malicious hardware, side-channel attacks.

## 5. Security Claims Policy (enforced by `research/tests/test_claims.py`)
Docs, code comments and UI must not claim "100 % secure". Allowed wording: *defense in depth*, with each guarantee tied to a named test or a named residual risk in the table above. <!-- claims-lint: quote -->
